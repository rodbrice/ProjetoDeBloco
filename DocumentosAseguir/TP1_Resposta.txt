Definição de Escopo e Objetivos: Qual é o objetivo principal da aplicação web
que desenvolveremos e quais funcionalidades específicas devem ser incluídas
para atender às necessidades do escopo definido pelo professor?
R: O objetivo principal desta aplicação é prover serviços de atendimentos psicológicos, com
área específica de anotações; calendário acessível com marcações onde se encontram os
serviços agendados; local de preenchimento de dados profissional/paciente, possuindo tipos
de perfis diferentes; pesquisa por local, especialidade, horários disponíveis e valores;
sistema de voluntários: pesquisadores, estudantes, profissionais que buscam oferecer
serviços voluntários podem se inscrever através de área específica no próprio site; parcerias
com casas de repouso e centros de reabilitação, cujo valor se dilui na mensalidade dos
familiares (incluir em recibo gerado em uma página diferente); aba de pagamentos; todos os
logins serão checados através de ferramentas de verificação.
Gestão Ágil do Projeto: Como organizaremos o trabalho seguindo os preceitos
do Agile Scrum?
R: O grupo (Brice, Karina e Sâmela) será organizado e dividido por responsabilidades de
acordo com as funcionalidades. Inicialmente, o trabalho será baseado nos user stories
definidos no planejamento da sprint e adicionados a este documento.
Um Drive foi criado para o compartilhamento das informações do projeto, incluindo um
modelo de documento para anotações das reuniões futuras. Todos os membros da equipe
têm acesso às informações compartilhadas nesse Drive.
A comunicação assertiva é o foco, garantindo um bom follow-up, mesmo nas reuniões orais.
As notas das reuniões serão registradas em um documento compartilhado, e o Google Meet
será utilizado como ferramenta de chamada, principalmente pelo fator Gemini Notes, que
oferece transcrição de áudio e sumarização dos principais tópicos discutidos. Dessa forma,
o processo de troca de ideias e construção do projeto será mantido de forma clara e
organizada.
Os códigos serão compartilhados via Git na página do projeto para que esteja de fácil
acesso para todos os desenvolvedores envolvidos no processo de desenvolvimento que farão o processo em conjunto
mas manterão os códigos dentro da mesma pasta para verificação e compartilhamento.

CRIAÇÃO DE HISTÓRIAS DE USUÁRIO
História de Usuário #1 - Busca de Psicólogos (Paciente)
Como Maria, 28 anos, estudante universitária com ansiedade,
Eu quero encontrar um psicólogo perto da minha casa que atenda pelo preço que posso
pagar,
Para que eu consiga começar meu tratamento sem precisar viajar muito ou gastar além do
meu orçamento.
Critérios de Aceitação:
● Poder filtrar por bairro, especialidade (ansiedade, depressão, etc.) e faixa de preço
● Sistema busca CEP automaticamente via API externa
● No celular, arrastar o card do psicólogo para a direita salva nos favoritos
● Arrastar para a esquerda descarta da lista
● Funciona bem tanto no celular quanto no notebook
● Resultados aparecem em até 3 segundos
História de Usuário #2 - Modo Alto Contraste (Acessibilidade)
Como João, 45 anos, com baixa visão devido à degeneração macular,
Eu quero poder aumentar o contraste das cores da tela,
Para que eu consiga ler os textos e usar o aplicativo sem forçar minha visão ou pedir ajuda.
Critérios de Aceitação:
● Segurar o dedo no logo por 2 segundos ativa/desativa o modo
● Cores com contraste forte (preto/branco ou amarelo/preto)
● Aplicativo lembra da minha escolha quando eu voltar
● Letras ficam maiores automaticamente
● Todos os botões grandes o suficiente para tocar sem errar
História de Usuário #3 - Gestão de Agenda (Psicólogo)
Como Dra. Ana Paula, psicóloga clínica com consultório próprio,
Eu quero visualizar minha agenda semanal e fazer anotações sobre cada paciente após as
sessões,
Para que eu consiga organizar meus atendimentos e manter registro atualizado de cada
caso sem usar cadernos físicos.
Critérios de Aceitação:
● Calendário mostrando todos os agendamentos da semana
● Ao clicar no horário, abrir ficha do paciente
● Área de anotações com salvamento automático
● Histórico de sessões anteriores acessível
● Notificação 15 minutos antes de cada consulta
● Acesso rápido pelo celular entre atendimentos

FRAMEWORK: JUSTIFICATIVA PARA UTILIZAÇÃO DE
REACTJS E REACT NATIVE
Análise da Escolha Tecnológica
Considerando o escopo do projeto MindCare e o perfil da equipe de desenvolvimento, a
escolha dos frameworks ReactJS (versão web) e React Native (versão mobile) se
fundamenta nos seguintes aspectos:
1. Reutilização de Código e Componentização
A arquitetura baseada em componentes do React permite desenvolver elementos isolados e
reutilizáveis. Esta abordagem facilita a divisão de tarefas entre os três integrantes da
equipe, em que cada componente pode ser desenvolvido de forma independente e
posteriormente integrado. Por exemplo, um componente "CardPsicologo" pode ser utilizado
em múltiplas telas da aplicação sem necessidade de reescrita.
2. Compatibilidade Cross-Platform
O requisito do projeto de possuir versões web e mobile é atendido eficientemente através da
combinação ReactJS + React Native. Ambas as tecnologias compartilham a mesma lógica
de programação e princípios de componentização, permitindo reaproveitamento de
aproximadamente 60-70% do código entre as plataformas. Isto otimiza significativamente o
tempo de desenvolvimento.
3. Ecossistema e Documentação
React possui uma comunidade ampla e ativa, resultando em:
● Extensa documentação oficial
● Abundância de recursos educacionais (tutoriais, cursos, artigos)
● Bibliotecas de terceiros testadas e mantidas
● Suporte comunitário através de fóruns especializados.
